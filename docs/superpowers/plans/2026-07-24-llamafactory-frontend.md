# VisiOX 大模型训练前端页面规划

## 1. 页面目标

在现有“模型空间 -> 创建产线”逻辑中，为 `task=llm` 提供独立的四步配置内容，继续复用全局顶部栏、左侧导航、模型空间列表和产线状态体系。

第一版前端只覆盖真正可验收的能力：

- 监督微调 SFT。
- 单机单卡 NVIDIA GPU。
- LoRA、4-bit QLoRA。
- Hugging Face、ModelScope 公共模型。
- Alpaca、ShareGPT/OpenAI messages 数据集。
- 参数表单和 YAML 配置双向切换。
- 资源选择、显存预检、提交、停止和恢复反馈。

不把 LLaMA-Factory WebUI 嵌入 VisiOX，也不把它的整张参数表原样复制到页面。VisiOX 负责组织用户流程，LLaMA-Factory 只作为训练引擎。

## 2. 视觉与交互原则

- 保持当前 VisiOX 白色内容区、浅灰分隔线、品牌蓝主操作色，不引入紫色 AI 渐变或营销式大卡片。
- 使用现有四步顶栏，固定在页面顶部中央；步骤可返回，未完成前置校验时不能跳到后续步骤。
- 页面主体最大宽度 `1440px`，表单采用 12 列栅格；不随浏览器缩放任意挤压。
- 主操作区每屏只保留一个蓝色主按钮，次要操作使用描边或文字按钮。
- 复杂参数渐进展开：常用配置直接展示，LoRA、训练稳定性、日志与保存、数据性能分别折叠。
- 所有异步字段提供加载、成功、失败和重试状态；错误显示在对应字段下，不只弹全局 toast。
- 长表单自动保存草稿，返回模型空间后仍显示“配置中”。
- 页面切换使用 180-220ms 的透明度/位移动效，并支持 `prefers-reduced-motion`。

## 3. 入口与页面骨架

创建产线弹窗中的“大模型训练”卡片保持现有入口。点击“创建产线”后立即创建草稿，并进入：

```text
返回产线列表              1 选择产线 -- 2 数据准备 -- 3 参数准备 -- 4 提交训练

┌────────────────────────────────────────────────────────────────────────────┐
│ 步骤标题                                              草稿已自动保存 10:32 │
├────────────────────────────────────────────────────────────────────────────┤
│                              当前步骤内容                                  │
├────────────────────────────────────────────────────────────────────────────┤
│ 上一步                                             保存草稿       下一步  │
└────────────────────────────────────────────────────────────────────────────┘
```

把当前单文件中的向导拆成 `PipelineWizardShell`。CV 和 LLM 共享外壳，各自渲染步骤内容。步骤写入 URL：

```text
/model-space?pipeline=<id>&step=data
```

这样刷新、前进后退和从“配置中”产线再次进入都能恢复到正确步骤。

## 4. 第一步：选择产线

该步骤用于确认产线类型和当前支持范围，不再次选择任务。

```text
选择产线

产线名称  [ 大模型微调产线 01                                  ]

任务场景
┌────────────────────────────────────────────────────────────────────────────┐
│ [CPU 图标] 大模型训练                         监督微调 SFT                 │
│ 使用 LoRA / QLoRA 对文本大模型进行领域微调                                │
│ 当前版本：文本模型 · 单机单卡 NVIDIA GPU                                  │
└────────────────────────────────────────────────────────────────────────────┘
```

交互规则：

- 产线名称失焦校验：必填、最长 64 字符、同一用户下不能重名。
- DPO、全参数微调、多模态仅作为“暂未开放”说明，不显示可点击控件。
- 点击“下一步”前自动保存名称、`task=llm`、`engine=llamafactory`。

## 5. 第二步：数据准备

页面采用上下两个完整区块。先解析模型，再用该模型的 tokenizer 分析数据。

### 5.1 基础模型

```text
基础模型

模型来源       ( Hugging Face ) ( ModelScope )
模型 ID        [ Qwen/Qwen3-0.6B                               ] [解析模型]
版本 Revision  [ main                                          ]

解析完成
Qwen3 · CausalLM · 0.6B 参数 · Apache-2.0 · 需要 1.2 GB 下载
最终版本：<resolved commit>        对话模板：qwen3（系统识别）
```

| 页面字段 | 控件 | 规则 |
|---|---|---|
| 模型来源 | 分段控件 | 第一版 Hugging Face / ModelScope |
| 模型 ID | 可搜索输入 | 支持目录搜索和手动输入仓库 ID |
| Revision | 输入框 | 默认 `main`，解析后展示不可变 commit |
| 对话模板 | 只读结果 + 高级覆盖 | 默认自动识别，覆盖时显示风险提示 |
| `trust_remote_code` | 风险开关 | 默认关闭，仅白名单模型允许开启 |

“语言”是 LLaMA-Factory WebUI 自身语言，不是训练参数，不进入本页面。“模型路径”由边缘缓存生成，用户不填写。

### 5.2 训练数据集

```text
训练数据集

数据集 [ 请选择已校验的大模型数据集                         v ] [查看详情]

格式：ShareGPT       样本：2,480       有效：2,463       无效：17

┌──────────────────────────── 对话预览 ─────────────────────────────────────┐
│ system     你是一名设备维护助手                                           │
│ user       电机温度持续升高应该检查什么？                                 │
│ assistant  先检查负载、电流、散热和轴承状态……                             │
└────────────────────────────────────────────────────────────────────────────┘

Token 长度分布       P50 412 · P95 1,376 · 最大 5,201
[长度分布图]          当前截断长度 1,024，预计 8.4% 样本会被截断
```

交互规则：

- 只列出 `task=llm`、已校验且与 SFT 兼容的数据集。
- 数据集改变后自动重新执行格式校验和 token 统计，期间用稳定高度骨架屏。
- 无效样本可查看错误清单：缺失 assistant、角色顺序错误、空文本、无法解析。
- “查看详情”打开抽屉，不离开创建产线；抽屉包含字段映射、样本预览和校验报告。
- 数据集没有可训练 assistant 响应时禁止下一步，并提供返回数据集修复入口。

### 5.3 兼容性结果

模型和数据都选择后显示：

```text
[通过] 模型模板与数据格式兼容，可进入参数配置
```

失败时必须说明具体原因和修复动作，不使用“配置不兼容”这类笼统提示。

## 6. 第三步：参数准备

页头右侧使用分段控件切换“表单配置 / YAML 配置”。

### 6.1 推荐方案

```text
参数准备                                      [表单配置 | YAML 配置]

微调方案
( LoRA  推荐 )   ( QLoRA  低显存 )

系统建议：当前 RTX 3060 12GB 建议 QLoRA、cutoff 1024、batch 1、梯度累积 8
```

资源尚未选择时显示保守默认值，并在第四步重新校验。

### 6.2 基础参数

桌面端使用三列字段，窄屏降为两列或单列：

| 中文名称 | 字段 | 默认值 |
|---|---|---|
| 训练阶段 | `stage` | SFT，只读 |
| 微调方法 | `finetuning_type` | LoRA |
| 量化等级 | `quantization_bit` | LoRA 为无，QLoRA 为 4 |
| 学习率 | `learning_rate` | `1e-4` |
| 训练轮数 | `num_train_epochs` | `3` |
| 截断长度 | `cutoff_len` | `1024` |
| 单卡批量 | `per_device_train_batch_size` | `1` |
| 梯度累积 | `gradient_accumulation_steps` | `8` |
| 验证集比例 | `val_size` | `0.1` |
| 调度器 | `lr_scheduler_type` | cosine |
| 热身比例 | `warmup_ratio` | `0.1` |
| 计算精度 | `bf16/fp16` | 自动 |

每个字段显示单位、有效范围和一句说明。数值不用滑块，避免难以精确输入。

### 6.3 高级参数

按四组折叠：

1. LoRA 配置：rank、alpha、dropout、target。
2. 训练稳定性：max grad norm、seed、gradient checkpointing、flash attention、RoPE。
3. 日志与保存：logging steps、eval steps、save steps、save total limit。
4. 数据性能：max samples、packing、预处理 workers、dataloader workers。

每组标题右侧显示“已修改 N 项”，提供“恢复推荐值”。

### 6.4 YAML 模式

```text
┌──────────────────────── YAML 编辑器 ──────────────────────────────────────┐
│ stage: sft                                                                │
│ finetuning_type: lora                                                     │
│ learning_rate: 0.0001                                                     │
│ ...                                                                       │
└────────────────────────────────────────────────────────────────────────────┘
配置校验：通过 · 27 个用户参数 · 8 个系统托管参数
```

- 表单切到 YAML 时生成当前配置；YAML 切回表单前先校验并同步字段。
- 错误显示行号、字段和修复建议；失败时不能退出 YAML 模式或进入下一步。
- 系统托管字段只读展示：模型路径、数据路径、输出/日志目录、训练镜像、分布式变量、真实断点路径。
- 提供“恢复推荐配置”和“复制配置”，不提供任意 Shell 或环境变量入口。

## 7. 第四步：提交训练

LLM 第一版不显示“本机 CPU”，直接进入远程 GPU 资源选择。

### 7.1 资源选择

```text
训练资源

资源池 [ x86 NVIDIA GPU                                           v ]

服务器与 GPU
┌────────────────────────────────────────────────────────────────────────────┐
│ ● edge-10-10-13-20                                      已选择             │
│ NVIDIA RTX 3060 · 12 GB · 空闲 10.8 GB · x86_64 · 在线                     │
│ 模型缓存：未命中 · 预计下载 1.2 GB        磁盘可用 286 GB                  │
└────────────────────────────────────────────────────────────────────────────┘
```

- 只显示在线、架构兼容且有 NVIDIA GPU 的节点。
- 第一版 GPU 数量固定为 1，仅展示，不用可编辑步进器。
- 训练镜像摘要由系统管理，普通用户页面完全不显示输入框。

### 7.2 预检与自动优化

```text
训练预检
[通过] GPU 架构与精度兼容
[通过] 数据集 2,463 个有效样本
[提示] 模型首次运行需下载约 1.2 GB
[警告] 预计峰值显存 11.4 GB，已自动启用 gradient checkpointing

自动优化  [开启]
调整：LoRA -> QLoRA · cutoff 2048 -> 1024 · batch 2 -> 1
```

- 自动优化的修改必须列出前后值，用户确认后才写回参数。
- 硬性失败（显存仍不足、磁盘不足、节点离线、模型许可未确认）禁用提交。
- 预检可重新运行，资源状态显示最后更新时间。

### 7.3 提交摘要

```text
模型  Qwen/Qwen3-0.6B @ <commit> · QLoRA 4-bit
数据  equipment-sft-v1 · 2,463 个有效样本
训练  3 epochs · cutoff 1024 · effective batch 8
资源  edge-10-10-13-20 · RTX 3060 12 GB

                                              [保存草稿] [提交训练]
```

提交后在原位置展示排队、准备模型、准备数据、启动容器四个阶段。创建成功后跳到产线详情/可视化训练。

## 8. 草稿、校验和异常状态

- 字段改变 500ms 后自动保存；顶部展示“保存中 / 已保存 / 保存失败，重试”。
- 重新进入“配置中”产线时恢复上次有效步骤、表单模式和折叠状态。
- 模型解析、数据校验、参数校验、资源预检分别有独立空状态和重试按钮。
- 节点提交前离线时保留配置，清空失效节点并要求重选。
- 切换 LoRA/QLoRA 只修改相关默认字段，不覆盖其他手动配置。
- 返回产线列表不丢草稿；有未保存修改时显示离开确认。

## 9. 响应式规格

| 内容宽度 | 布局 |
|---|---|
| `>= 1360px` | 12 列；参数三列；资源与预检 8:4 |
| `1024-1359px` | 参数两列；资源与预检上下排列 |
| `768-1023px` | 单列；步骤名称保留；底部操作栏固定 |
| `< 768px` | 只保证查看和草稿编辑，不承诺完整生产配置体验 |

固定尺寸：步骤圆点 24px、输入高度 40px、主按钮至少 88x40px、图表区使用固定 `aspect-ratio`。100%、125%、150% 缩放均不能出现横向滚动或字段遮挡。

## 11. 前端数据类型

```ts
type LlmModelSource = "huggingface" | "modelscope";
type LlmFineTuningMethod = "lora" | "qlora";

type LlmPipelineDraft = {
  pipelineId: string;
  name: string;
  engine: "llamafactory";
  model: {
    source: LlmModelSource;
    modelId: string;
    requestedRevision: string;
    resolvedRevision?: string;
    template?: string;
  };
  datasetId?: string;
  recipe: Record<string, unknown>;
  resource: { poolId?: string; nodeId?: string };
  lastValidStep: 0 | 1 | 2 | 3;
};
```

页面不直接把该结构原样提交给 Worker；API 返回模型解析、数据报告、配置校验和资源预检结果。

## 12. 前端验收标准

1. 创建“大模型训练”产线后立即在模型空间显示“配置中”。
2. 刷新、返回列表、重新进入后能恢复步骤和草稿。
3. 模型未解析或数据不兼容时无法进入参数步骤。
4. LoRA/QLoRA 切换正确更新量化字段，不覆盖无关手动配置。
5. 表单与 YAML 双向同步，错误能定位到具体行和字段。
6. LLM 页面不出现本机 CPU、YOLO 镜像摘要、类别数、图像切分和 mAP 字段。
7. 资源预检失败时不能提交，并显示可执行的修复建议。
8. 100%、125%、150% 浏览器缩放下布局稳定，无水平滚动和文字遮挡。
9. 键盘可完成四步配置，焦点顺序与视觉顺序一致。
10. CV/YOLO 创建产线页面和训练流程回归不受影响。

## 13. 实施顺序

1. 抽取共享 `PipelineWizardShell`，保持现有 CV 行为不变。
2. 实现 LLM 第一步和纯前端草稿状态。
3. 实现模型/数据步骤及骨架、空状态、错误状态。
4. 实现参数元数据、分组表单和 YAML 双向同步。
5. 实现资源选择、预检结果和提交摘要。
6. 接 API 后补齐真实解析、数据报告、参数校验和资源预检。
7. 使用 Playwright 截图验收 100%、125%、150% 缩放与 1024/1440/1920 宽度。
